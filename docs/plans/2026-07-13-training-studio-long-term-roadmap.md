# Training Studio 长期产品路线

## 背景

当前 `/training-studio` 已经完成 MVP 闭环：用户选择训练场景、难度、表达框架和模式后，系统创建 battle prep 房间，并进入 `/chat/:roomId` 完成对话练习、复盘和话术沉淀。

MVP 的重点是跑通“配置训练 -> 创建房间 -> 对话练习 -> 反馈复盘”的闭环。长期目标不应停留在三种输入方式，而应演进为一个高压沟通训练系统。

## 长期目标

Training Studio 的长期形态是：

> 用户配置训练目标、角色、场景和难度后，和一个可控的 AI stakeholder 进行多模态模拟沟通；系统在过程中提供提示和干预，在结束后复盘表现，并把能力增长沉淀到个人训练档案里。

最终产品闭环：

```text
训练目标 -> 场景模拟 -> 多模态对话 -> 实时提示 -> 结束复盘 -> 改进计划 -> 针对弱点继续训练
```

## 三种训练模式的目标形态

### 文字模式

定位：低成本、低压力的结构化表达训练。

长期效果：

- 像和挑剔面试官、客户、老板、评审委员进行文字对话。
- 训练用户如何组织答案、回应追问、拆解反对意见。
- 重点评估表达结构、论据质量、回答完整度和追问处理。

适合场景：

- 面试问答准备
- 客户异议处理
- 汇报材料答辩
- 结构化表达训练

### 语音模式

定位：接近电话沟通的实时口头训练。

长期效果：

- 用户点开始后直接说话，AI stakeholder 用语音回应。
- 支持自然插话、打断、追问、沉默和压力升级。
- AI 能根据用户语速、停顿、含糊、跑题和犹豫调整压力。
- 结束后反馈表达结构、说服力、语气、停顿、废话率和关键点遗漏。

这不是“录一段再识别”的最终形态，而是实时双向语音对话。

优先级判断：语音实时对话应是 MVP 后最值得优先强化的方向，因为它最接近真实沟通，也最能体现训练价值。

### 视频模式

定位：视频会议、面试、路演、答辩等镜头前表达训练。

长期效果分两层：

1. 用户侧表现分析：打开摄像头，分析用户眼神、表情、语速、停顿、姿态、紧张程度、是否看稿、是否缺乏自信。
2. 对话对象呈现：提供 AI stakeholder 的会议式对话界面、视频头像或虚拟人，让用户感觉自己在面对真实的人。

最终效果：

- 用户看到一个对话对象或会议场景。
- 用户开摄像头实时作答。
- AI stakeholder 用语音、表情或状态反馈施压。
- 系统同时分析语言和非语言表现。
- 结束后给出视频级复盘：表情、眼神、语气、结构、说服力和镜头表现。

视频模式不只是录制视频上传，而应逐步演进为真实会议式训练。

## 技术路线分层

文本、语音、视频不要各自发展成三套产品逻辑。长期应统一为同一个训练核心引擎，再由不同输入输出模式接入：

```text
训练核心引擎 = 场景 + persona + 对话状态 + LLM 回复 + 评估 + 成长记录
```

| 模块 | 技术路线 |
|:---|:---|
| 文本对练核心 | 保持当前项目 |
| 文本聊天 UI/交互 | 可借鉴 LibreChat |
| 会话列表/搜索/消息编辑/重试/分支 | 可借鉴 LibreChat |
| 通用模型配置/多模型 provider | 可借鉴 LibreChat |
| 训练逻辑 / persona / 评估 / 成长 | 不借 LibreChat，保留自研 |
| 语音免提链路 | 用 Pipecat |
| 视频 / 多人实时房间 | 后面再评估 LiveKit |

路线判断：文本模式保留现有训练闭环，LibreChat 只作为成熟聊天产品参考；语音模式优先用 Pipecat 替换底层实时语音链路；视频和多人实时房间等能力，在进入会议式训练阶段后再评估 LiveKit。

## 阶段路线

### Phase 0: MVP 闭环

当前状态：

- 训练页提供文字、语音、视频三种模式选择。
- 三种模式都会创建 battle prep 房间，并进入统一聊天页。
- 文字输入已可完成基本一问一答。
- 语音能力偏“录音 -> 转写 -> 聊天”，不是实时电话式沟通。
- 视频能力偏“录制用户视频回答”，不是实时视频会议。

### Phase 1: 强化文字训练质量

目标：

- 将训练模式、场景、难度、表达框架更明确地注入 stakeholder 行为。
- 优化首轮问题、追问策略、压力升级和结束条件。
- 让复盘报告直接对应本轮训练目标。

验收方向：

- AI stakeholder 能按不同模式呈现不同沟通风格。
- 对话过程有明确回合目标和难度变化。
- 复盘能指出结构、证据、表达和追问处理问题。

### Phase 2: 实时语音训练

目标：

- 从录音转写式语音升级为实时双向语音沟通。
- 支持 AI 语音输出、用户实时输入、打断和低延迟反馈。
- 复盘增加语音维度：停顿、语速、重复、犹豫、填充词、语气稳定性。

验收方向：

- 用户可以像打电话一样完成一轮训练。
- AI 可以语音追问和打断。
- 系统能在结束后给出口头表达指标。

### Phase 3: 视频回答与镜头表现分析

目标：

- 保留当前视频录制能力，但将其纳入可评分训练流程。
- 分析用户视频回答中的语言和非语言表现。
- 生成视频级反馈，包括眼神、姿态、紧张感、镜头感和表达结构。

验收方向：

- 用户的视频回答可以被纳入同一份训练报告。
- 报告区分“内容表达”和“镜头表现”。
- 用户能看到可执行的改进建议。

### Phase 4: 会议式 AI stakeholder

目标：

- 在视频模式中提供可视化对话对象。
- AI stakeholder 具备语音、表情、状态和压力反馈。
- 支持面试、销售、路演、答辩、管理沟通等高仿真场景。

验收方向：

- 用户有“面对真实对话对象”的训练感。
- AI 角色行为和 persona、组织关系、隐藏议程一致。
- 训练结束后沉淀为个人能力画像和下一轮训练计划。

## 产品效果指标

长期应关注以下指标：

- 完成率：用户能否完成一轮训练。
- 复训率：用户是否愿意针对弱点再次训练。
- 压力真实性：用户是否感到对话像真实 stakeholder。
- 改进可执行性：复盘是否能给出下一次可练的动作。
- 能力沉淀：系统是否能长期追踪用户表达能力变化。

## 近期建议

下一阶段优先顺序：

1. 先把文字训练的追问策略、难度控制和复盘质量做扎实。
2. 再把语音模式升级为实时双向语音沟通。
3. 视频模式先做用户侧视频回答分析，再做 AI 可视化对话对象。

这样可以避免过早投入高成本视频虚拟人，同时持续增强真实训练价值。
